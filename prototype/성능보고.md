# 성능보고 — 「조선의 왕」 태조 장면 그래픽 시제품 (1B)

2026-10-20. 이 PC(인텔 내장 그래픽 **UHD Graphics 770**, 크롬 155)에서 잰 값이다.

## 담임용 디벗 점검 순서 (5줄)

1. 디벗 크롬에서 받은 주소를 연다(주소는 아직 없음 — 아래 「디벗 확인용 주소」). 5초 안에 「조선의 왕」 제목 화면이 뜨면 통과.
2. 주소 끝에 `?debug=1` 을 붙여 다시 연다(예: `…/index.html?debug=1`). 왼쪽 위에 검은 점검 상자가 뜬다.
3. 「시작하기」를 누르고 카드를 끝까지 넘긴 뒤(도성 완성 장면까지), 점검 상자의 **fps 숫자**와 **화질(높음/보통/낮음)** 을 읽는다.
4. 맨 아래 **GPU 줄**(그래픽 칩 이름)을 사진으로 찍거나 그대로 적는다.
5. 이 세 가지(fps, 화질, GPU 이름)와 "버벅였다/부드러웠다" 한 마디를 알려 주면 된다. fps가 30 아래면 `?q=low` 를 붙여 한 번 더 본다.

## 예산 대비 결과 (보통 화질, 1366×768)

| 항목 | 예산 | 결과 | 판정 |
|---|---|---|---|
| 그리기 호출 | 120회 이하 | 평소 19~26회, 가장 많을 때 36회(건물이 생기며 그림자를 다시 굽는 순간) | 통과 |
| 삼각형 | 20만 개 이하 | 평소 7.7만(빈 섬)~12.9만(도성 완성), 가장 많을 때 19.3만(그림자 다시 굽는 순간) · 높음 19.7만 | 통과(여유 적음) |
| 첫 내려받기 | 3MB 이하(압축 기준) | 압축 **347KB** (압축 전 955KB, 파일 11개) | 통과 |
| 첫 화면 | 5초 안 | 이 PC 로컬 서버에서 0.86초 | 통과(교실 와이파이는 디벗에서 확인) |
| fps | 보통 60, 최소 30 | 모든 화질·모든 장면 60fps(화면 주사율 한도) | 통과 |
| CPU 6배 느리게 | 30fps 이상 | 모든 화질·모든 장면 60fps | 통과 |

- 압축 크기: three.min.js 161KB + 내 코드 47KB + 글꼴 132KB(woff2는 이미 압축) + 기타. GitHub Pages는 gzip으로 보내므로 디벗 30대가 동시에 받아도 약 10MB다.
- "CPU 6배 느리게"는 크롬 개발자 도구와 같은 장치(`Emulation.setCPUThrottlingRate 6`)로 걸었다. 실제로 걸린 것을 확인했다(같은 계산이 28ms → 177ms).

## 그래픽 칩의 실제 여유 (60fps 제한을 풀고 잰 최대 fps)

CPU 6배 느리게는 그래픽 칩을 느리게 하지 못한다. 디벗의 약한 점은 그래픽 칩이므로, 화면 주사율 제한을 풀고 이 PC 그래픽 칩의 최대 fps를 쟀다.

| 화면 | 화질 | 플레이 | 다 지은 뒤 | 실각(수묵) |
|---|---|---|---|---|
| 1366×768 | 높음 | 121 | 114 | 105 |
| 1366×768 | 보통 | 268 | 227 | 185 |
| 1366×768 | 낮음 | 427 | 357 | 283 |
| 1920×1080 | 높음 | 80 | 67 | 59 |
| 1920×1080 | 보통 | 152 | 126 | 104 |
| 1920×1080 | 낮음 | 262 | 225 | 176 |

**디벗 예상(추정, 확인 필요)**: 보급형 크롬북의 내장 그래픽은 UHD 770보다 대략 3~4배 느리다고 본다. 그러면 1366×768에서 보통 ≈ 55~75fps, 낮음 ≈ 90~120fps, 1920×1080 보통 ≈ 30~40fps다. 1080p 디벗에서 보통이 느리면 자동 전환이 낮음으로 내린다. 이 추정은 디벗에서 `?debug=1`로 꼭 확인해야 한다.

## 화질 3단계

| | 높음 | 보통 | 낮음 |
|---|---|---|---|
| 해상도 배율 상한 | 1.5 | 1.0 | 0.8 |
| 계단 줄이기 | MSAA 4배 | FXAA | FXAA |
| 그림자 | 2048, 부드러운(PCFSoft) | 1024, 일반(PCF) | 없음(미리 칠한 바닥 음영만) |
| 틸트시프트·빛 번짐 | 켬 | 켬 | 끔 |
| 걷는 사람 최대 / 구름 | 80 / 90% | 64 / 80% | 36 / 55% |

- **자동 전환**: 처음 1.5초 뒤부터 2.5초 동안 프레임 시간을 재서(중앙값) 24ms보다 느리면 한 단계 내리고, 보통에서 18ms보다 빠르면서 그래픽 칩이 외장급(NVIDIA·Radeon RX·Apple M)이면 높음으로 올린다. 그 뒤에도 3초 평균이 36ms보다 느리면 한 번 더 내린다. 소프트웨어 렌더러(SwiftShader 등)면 처음부터 낮음. 이 PC는 보통을 골랐다.
- 고정: 설정(톱니바퀴)에서 고르거나 주소 끝 `?q=low` / `?q=normal` / `?q=high`.
- 낮음에서도 싸 보이지 않게: 모든 모형의 바닥 쪽을 미리 어둡게 칠했고(AO), 건물이 생길 때 땅에 접촉 그림자를 칠한다.

## 아끼는 방법(제작서 필수 항목) 적용

- 인스턴싱: 집 2종, 나무 3종, 사람(몸 + 모자 4종), 성벽 마디, 구름, 떠 있는 바위, 새 — 각각 그리기 호출 1회.
- 건물은 합친 지오메트리 하나: 경복궁(궁장·광화문·회랑·근정전·전각)이 통째로 1회, 종묘·숭례문·흥인지문도 각 1회. 모든 모형이 재질 하나를 같이 쓴다.
- 그림자는 건물이 생길 때·하루의 빛이 바뀔 때만 다시 굽는다(`shadowMap.autoUpdate = false`).
- 해상도 배율 상한(위 표), 25초 동안 손대지 않고 움직이는 연출도 없으면 그리기를 반으로 쉰다(점검 화면에 "쉬는 중"), 탭이 숨으면 멈추고 소리도 멈춘다.
- 하늘은 맨 나중에 빈 곳만 칠한다. 보통 화질은 MSAA 대신 FXAA, 부드러운 그림자 대신 일반 그림자. 세 가지를 바꾸기 전과 뒤의 보통 화질 최대 fps(1366×768, 다 지은 뒤, 제한 해제): 101 → 227.
- WebGL 문맥 잃음: `?debug=1`의 「문맥 잃기 시험」으로 잃었다가 되살려 이어서 놀이가 되는 것을 확인했다.

## 확인한 것

- **이 PC 크롬**(창 없는 크롬을 개발자 도구 프로토콜로 조종): 시작 → 카드 끌기(게이지 미리 빛나기 확인) → 경복궁·종묘·초가 마을·성곽·숭례문·흥인지문·기와집 마을이 차례로 "뽕" → 해 질 녘 도성 완성(카메라가 한 바퀴) → 다시 하기 → 키보드 ←/→. 모두 들어주면 5장째 국고 0으로 실각(수묵화) → 다시 하기. 콘솔 오류 0건.
- **내장 브라우저**: 같은 흐름(시작 → 키보드로 끝까지 → 도성 완성 7개 모두 지음 → 다시 하기 → 모두 들어줘 실각 "나라 곳간이 텅 비었사옵니다.")을 오류 없이 확인.
- **file:// 더블클릭**: 서버 없이도 열리고 두 글꼴이 모두 읽힌다.
- **세로 화면**(768×1024, 412×860): 카드·게이지가 아래로 내려가고 깨지지 않는다.
- 소리: 오디오가 켜지는 것(`running`)과 오류 없음은 확인했지만, 귀로 듣는 확인은 하지 못했다. 담임이 디벗에서 들어 보고 크기를 정해 주면 된다.

## 담임이 정할 것

1. **디벗 확인용 주소**: 디벗에서 열려면 인터넷 주소가 필요하다. 새 GitHub 저장소를 만들고 Pages로 올려도 되는지(push = 공개). 승인 전까지 커밋도 하지 않았다.
2. **소리 기본값**: 지금은 효과음·배경음 모두 끔(수업 중 요청). 오른쪽 위 스피커 버튼으로 켠다(켜면 작은 소리). `js/audio.js` 맨 위 `DEFAULTS` 한 줄만 바꾸면 된다.
3. 건물 모양을 오늘날 모습으로 둘지, 태조 때 모습으로 바꿀지(CREDITS.md 「담임 확인이 필요한 점」).
